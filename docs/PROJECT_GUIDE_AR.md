# دليل مشروع سيارتي العراق

هذا الملف يشرح مشروع **سيارتي العراق** بأسلوب مبسط جداً. اعتبره خريطة كاملة: ماذا يفعل المشروع، أين توجد الملفات، كيف يدخل الطلب من المتصفح، كيف يمر على Django، كيف تُقرأ قاعدة البيانات، وكيف تظهر الصفحة للمستخدم.

الهدف أن تستطيع فتح المشروع وفهمه حتى لو كنت جديداً على البرمجة.

## 1. الفكرة العامة

الموقع اسمه **سيارتي العراق**. المستخدم يدخل الموقع حتى يعرف معلومات عملية عن سيارته.

الموقع يجاوب على أسئلة مثل:

- ما الزيت المناسب لسيارتي؟
- ما رقم الأوكتان المناسب؟
- ما حجم الإطار؟
- ما البطارية أو البلكات أو زيت الكير المناسب؟
- شنو الصيانة القريبة حسب الممشى؟
- إذا السيارة بيها عرض عطل، شنو الاحتمالات؟
- وين وكلاء الزيوت وقطع الغيار؟
- كيف أحصل على كود خصم من راعي؟

المشروع مبني بـ **Django**. Django هو إطار عمل بلغة Python لبناء المواقع.

فكر في Django كأنه مطعم:

- المتصفح هو الزبون.
- الرابط هو الطلب.
- `urls.py` هو الموظف الذي يعرف إلى أي مطبخ يرسل الطلب.
- `views.py` هو الطباخ الذي يحضر الرد.
- `models.py` هو المخزن وقاعدة البيانات.
- `templates/` هي الصحون وطريقة تقديم الطعام.
- `admin.py` هي غرفة الإدارة التي يدخلها صاحب المطعم لتعديل البيانات.

## 3. معنى `manage.py`

`manage.py` هو ملف تشغيل أوامر Django.

أمثلة:

```bash
python manage.py runserver --settings=config.settings
```

هذا يشغل الموقع محلياً.

```bash
python manage.py migrate --settings=config.settings
```

هذا يطبق تغييرات قاعدة البيانات.

```bash
python manage.py test --settings=config.settings
```

هذا يشغل الاختبارات.

لا تضع منطق الموقع داخل `manage.py`. هو فقط باب أوامر.

## 4. مجلد `config`

هذا هو إعدادات مشروع Django العام.

### 4.1 ملف `config/settings.py`

هذا الملف يقول لـ Django كيف يعمل المشروع.

أهم الأشياء فيه:

```python
BASE_DIR = Path(__file__).resolve().parent.parent
```

هذا يحسب مسار المشروع. يعني يقول: أين يوجد المشروع على الجهاز؟

```python
load_dotenv()
```

هذا يقرأ ملف `.env` إن وجد. ملف `.env` يستخدم للأسرار مثل `SECRET_KEY` وبيانات قاعدة البيانات.

```python
DEBUG = os.getenv('DEBUG', 'False').lower() == 'true'
```

هذا يقرر هل الموقع في وضع التطوير أم الإنتاج.

- `DEBUG=True`: مناسب للتطوير فقط.
- `DEBUG=False`: مناسب للإنتاج.

```python
INSTALLED_APPS = [
    'cars',
    'django.contrib.admin',
    ...
]
```

هنا تقول لـ Django: هذه التطبيقات موجودة في المشروع. أهم تطبيق عندنا هو `cars`.

```python
MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',
    'cars.security.SecurityHeadersMiddleware',
    'whitenoise.middleware.WhiteNoiseMiddleware',
    ...
]
```

الـ Middleware مثل حارس يمر عليه كل طلب قبل أن يصل للصفحة وبعد أن يخرج الرد.

- `SecurityMiddleware`: حماية عامة من Django.
- `cars.security.SecurityHeadersMiddleware`: يضيف هيدرات أمان مخصصة.
- `WhiteNoiseMiddleware`: يخدم ملفات static مثل CSS وJS في الإنتاج.

```python
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.sqlite3',
        'NAME': BASE_DIR / 'db.sqlite3',
    }
}
```

محلياً يستخدم SQLite. إذا يوجد `DATABASE_URL` يستخدم قاعدة بيانات أخرى، غالباً PostgreSQL على السيرفر.

```python
TEMPLATES = [...]
```

هذا يحدد كيف يقرأ Django ملفات HTML.

داخل `context_processors` يوجد:

```python
'cars.context_processors.site_settings'
```

هذا يجعل إعدادات الموقع متاحة في كل القوالب باسم `site_settings`.

### 4.2 ملف `config/urls.py`

هذا الملف هو الخريطة الرئيسية للروابط.

أمثلة:

```python
path('robots.txt', robots_view, name='robots_txt')
```

إذا المستخدم طلب `/robots.txt` يتم تشغيل `robots_view`.

```python
path('sitemap.xml', sitemap_view, name='sitemap')
```

هذا يولد sitemap لمحركات البحث.

```python
path(_ADMIN_PATH, admin.site.urls)
```

هذا رابط لوحة الإدارة. المسار قابل للتغيير من `.env` عبر `ADMIN_URL`.

```python
path('', include('cars.urls'))
```

أي رابط لا يخص الإدارة أو الملفات العامة يذهب إلى `cars/urls.py`.

### 5.3 ملف `cars/views.py`

هذا أكبر ملف منطقي في المشروع. الدوال فيه تستقبل طلب المستخدم وتجهز الرد.

الفكرة العامة لكل view:

1. يستلم `request`.
2. يقرأ مدخلات من الرابط أو النموذج.
3. يقرأ بيانات من قاعدة البيانات.
4. يجهز قاموس context.
5. يرسل context إلى template.
6. يرجع HTML للمستخدم.

#### 5.3.1 `index_view`

يعرض الصفحة الرئيسية.

يجلب:

- البنرات.
- أحدث السيارات أو بيانات البحث.
- إعلانات البطاقات.
- إعدادات الموقع.

القالب المستخدم:

`cars/templates/cars/index.html`

#### 5.3.2 `search_view`

يعرض صفحة البحث عن السيارات.

يعتمد على دوال مساعدة:

- `_filters`
- `_apply`
- `_cached_lookup_data`
- `_search_context`

الفكرة:

- المستخدم يختار الماركة والموديل والسنة ومواصفات المنطقة.
- نوع المحرك والمحرك حقول اختيارية، لكن اقتراحات المحرك لا تُحمّل قبل اكتمال الحقول الأربعة الأساسية.
- الكود يبني QuerySet من `CarSpecification`.
- اختيار اقتراح المحرك يضبط نوعه تلقائياً حتى لا يختلط محرك 2.5 عادي بمحرك 2.5 هايبرد.
- الخادم لا يطبق فلتر محرك إذا لم ترافقه الماركة والموديل والسنة والمنطقة، حتى لو عُدّل رابط GET يدوياً.
- يفلتر النتائج بالسنة والمنطقة والمحرك المحدد بصورة صارمة.
- `_group_search_results` ينشئ بطاقة واحدة لكل ماركة + موديل + سنة + منطقة.
- اختلاف `trim` أو النص الحر في `spec` لا ينشئ بطاقة إضافية.
- إذا لم يحدد المستخدم محركاً، تظهر جميع المحركات المرتبطة داخل البطاقة نفسها.
- التوصيات المختلفة تبقى ضمن نطاق المحركات التي جاءت منها، ولا تُعمم قيمة على جميع المحركات بلا دليل.

#### 5.3.3 `maintenance_view`

هذه صفحة الصيانة والأعطال.

تعمل شيئين:

1. مستكشف أعراض الأعطال.
2. بطاقة صيانة حسب الممشى.

مدخلات الصيانة:

- `odometer`: الممشى.
- `engine_type`: نوع المحرك.
- `transmission`: نوع الكير.

خطوات عمل الصيانة:

1. يقرأ الممشى.
2. يجلب مهام الصيانة الفعالة.
3. يفلترها حسب الشركة إن وجدت.
4. يفلترها حسب نوع المحرك.
5. يفلترها حسب نوع الكير.
6. يجد أقرب `start_km` للممشى.
7. يبني `maintenance_summary`.
8. يعرض البطاقة في `maintenance.html`.

- `إذا موجود بسيارتك`.

- ضغط الإطارات وتدويرها كل 10,000 كم تقريباً إذا يسمح التصميم ونمط التآكل.
- متابعة سائل التبريد في الدبة والرديتر والخراطيم والمراوح.
- البطارية والشحن قبل الصيف.

### 5.4 ملف `cars/admin.py`

هذا يحدد ما يظهر في لوحة إدارة Django.

إذا `models.py` هو الجداول، فـ `admin.py` هو طريقة إدارة هذه الجداول.

#### أدوات قراءة Excel

في أول الملف توجد دوال مساعدة:

```python
def _text_value(row, *names):
```

تقرأ نص من صف Excel. تقبل أكثر من اسم عمود.

مثلاً تستطيع قراءة `name` أو `Name` أو `task_name`.

```python
def _int_value(row, name, default=0):
```

تحول قيمة إلى رقم.

```python
def _bool_value(row, name, default=True):
```

تحول قيمة إلى True أو False.

```python
def _sheet_rows(excel_file, preferred_names=None):
```

تقرأ ورقة Excel المفضلة وترجع الصفوف كقائمة dictionaries.

#### `import_symptoms_from_excel`

يستورد أعراض الأعطال وأسبابها من Excel.

يحتاج أعمدة مثل:

- `name`
- `slug`
- `category`
- `description`

نتائج البحث في `search.html` وصفحة تفاصيل السيارة في `recommendations.html` تستخدم منطق ثقة واضح بدل عرض كل شيء كأنه مؤكد.

التقسيم الحالي:

- `موثق`: السنة، نوع الوقود، الأوكتان، لزوجة زيت المحرك، ماركات الزيت، وسعة زيت المحرك عند توفرها.
- `عام`: لزوجة الزيت بعد 100 ألف كم وملاحظات الاستخدام الشاق في العراق.
- `تحقق قبل الشراء`: الإطارات، البلكات، البطارية، نوع الكير، زيت الكير، ماركات زيت الكير، كود المحرك، الفئة، والتوصيات التفصيلية.

القاعدة المهمة: الإطارات ليست ضمن البيانات الموثقة حالياً، وتظهر ضمن `تحقق قبل الشراء`.

نص التحذير المستخدم:

`قد تختلف هذه المعلومات حسب رقم الشاصي، المحرك، الفئة، والسوق. تحقق من دليل السيارة أو الوكيل أو مختص قبل شراء القطعة.`

قواعد بطاقة البحث الحالية:

- عدد البطاقات يحسب السيارات/السنوات/الأسواق، لا عدد صفوف قاعدة البيانات.
- الفئة لا تظهر في نموذج البحث، ويمكن إخفاؤها من بقية النتائج عبر `SiteSettings.hide_result_trim`.
- المحركات المرتبطة تظهر داخل بطاقة السيارة الواحدة.
- تفاصيل الزيت والكير والأوكتان وغيرها تُقرأ من الصفوف الأصلية؛ لا ينشئ التجميع توصية جديدة ولا يبدل المصدر.
- أحجام الخطوط الفنية في بطاقة البحث أكبر قليلاً من السابق لتحسين القراءة على الهاتف، من دون تغيير شبكة البطاقات.

المصطلحات المعتمدة في الواجهة:

- `البلكات` بدلاً من `البواجي`.
- `الكير` بدلاً من `القير` أو `ناقل الحركة` في التفاصيل الحساسة.
- `تحقق قبل الشراء` لكل قطعة حساسة.

## 8. الصيانة والأعطال بالتفصيل

صفحة الصيانة تخدم فكرتين.

### 8.1 الأعراض

المستخدم يختار عرض عطل.

الكود يبحث في `CarSymptom`.

إذا وجد العرض، يعرض:

- الوصف.
- أهم الأسباب.
- رابط التفاصيل.

### 8.2 الصيانة حسب الممشى

المستخدم يدخل ممشى السيارة.

مثلاً:

`40000`

الكود يبحث عن أقرب مرحلة صيانة في `MaintenanceTask.start_km`.

إذا المراحل:

```text
40000
45000
50000
```

والمستخدم أدخل:

```text
44000
```

الأقرب هو:

```text
45000
```

لأن الفرق 1000 فقط.

### 8.3 لماذا لا نعرض كل شيء؟

لأن المستخدم لا يريد قائمة كبيرة تخوفه.

بدل ذلك:

- نعرض بنود المرحلة التي تحتاج تحقق.
- نعرض الأشياء المشروطة إذا موجودة بالسيارة.
- نعرض ملاحظات ثابتة موثوقة.

### 8.4 الملاحظات الثابتة

هذه تظهر دائماً حتى لو نقصت بيانات المرحلة.

تشمل:

- الزيت والفلاتر.
- ضغط وتدوير الإطارات.
- التبريد.
- البطارية والشحن.
- أن أجواء العراق استخدام شاق.
- الرجوع لدليل الشركة.

## 9. نظام قفل البطاقات

المطلوب: البطاقة تبقى ظاهرة، لكن عند الضغط تظهر رسالة بدلاً من فتح الصفحة.

تمت إضافته في `SiteSettings`.

حقول البحث:

- `lock_search_card`: هل بطاقة البحث مقفولة؟
- `search_lock_message`: الرسالة التي تظهر عند الضغط.

حقول حاسبة الوقود:

- `lock_mix_card`: هل بطاقة حاسبة الوقود مقفولة؟
- `mix_lock_message`: الرسالة التي تظهر عند الضغط.

حقول الوكلاء:

- `show_dealers_card`: هل تظهر البطاقة؟
- `lock_dealers_card`: هل البطاقة مقفولة؟
- `dealers_lock_message`: الرسالة التي تظهر.

حقول الصيانة:

- `show_maintenance_card`
- `lock_maintenance_card`
- `maintenance_lock_message`

القاعدة:

- بطاقتا البحث والحاسبة ظاهرتان دائماً، لكن يمكن قفلهما برسالة.
- بطاقتا الوكلاء والصيانة لديهما خيار إظهار/إخفاء بالإضافة إلى خيار القفل.
- إذا `show=False`: البطاقة لا تظهر، وهذا ينطبق على الوكلاء والصيانة.
- إذا `show=True` و`lock=False`: البطاقة تظهر وتفتح الرابط.
- إذا `show=True` و`lock=True`: البطاقة تظهر، وعند الضغط تظهر الرسالة.
- إذا لم تُكتب رسالة قفل مخصصة، يظهر النص الافتراضي: `هذه الخدمة غير متاحة حالياً، ترقبوها قريباً.`

## 10. نظام SEO

الصفحة الرئيسية تستخدم SEO باسم:

`سيارتي العراق - دليل مواصفات السيارات والصيانة`

لكن اللوگو المرئي يبقى:

`سيارتي`

هذا يفيد Google بدون تغيير هوية الموقع في التصميم.

### 10.1 sitemap والفهرسة

`sitemap.xml` يولد من `sitemap_view` في `cars/views.py`.

حالياً يركز على:

- الصفحة الرئيسية.
- صفحة البحث.
- حاسبة الوقود.
- من نحن.
- الخصوصية.
- الوكلاء إذا كانت البطاقة مفعلة.
- الصيانة إذا كانت البطاقة مفعلة.
- صفحات أعراض الأعطال الفعالة.

تمت إزالة روابط `/car/<id>/recommendations/` من sitemap مؤقتاً لتقليل الصفحات الضعيفة أو المتكررة التي قد تظهر في Google Search Console كـ `تم اكتشاف الصفحة - لم تتم فهرستها`.

مهم: تنظيف sitemap لا يعني أن Google سيغيّر حالة الفهرسة فوراً. Google يحتاج وقتاً لإعادة الزحف وإعادة تقييم الصفحات من Search Console.

### 10.2 PWA وتثبيت iPhone

الموقع يدعم PWA عبر:

- `/manifest.json` من `manifest_view`.
- `/sw.js` من `sw_view`.
- أيقونات PWA داخل `cars/static/shared/icons/`.
- أيقونة Apple القياسية: `apple-touch-icon.png` بحجم `180x180`.

على Android قد يظهر تثبيت مباشر من المتصفح إذا توفرت شروط PWA.

على iPhone لا يعمل التثبيت بزر مباشر من JavaScript، لذلك عند ضغط زر `ثبّت التطبيق` تظهر تعليمات واضحة:

- افتح الموقع من Safari، وليس Chrome أو Facebook أو Google app.
- اضغط زر المشاركة.
- اختر `إضافة إلى الشاشة الرئيسية`.
- اضغط `إضافة`.

هذه التعليمات موجودة في `index.html` و`search.html` داخل نافذة `pwaModal`.

## 14. ما معنى migration؟

عندما تعدل `models.py` وتضيف حقل جديد، قاعدة البيانات لا تعرف عنه تلقائياً.

لذلك تعمل:

```bash
python manage.py makemigrations cars --settings=config.settings
```

هذا ينشئ ملف داخل:

`cars/migrations/`

ثم:

```bash
python manage.py migrate --settings=config.settings
```

هذا يطبق التغيير على قاعدة البيانات.

## 15. شرح مبسط لمفاهيم Django

### Model

جدول في قاعدة البيانات.

### Field

عمود داخل الجدول.

مثال:

```python
name = models.CharField(max_length=100)
```

يعني عمود نصي اسمه `name`.

### View

دالة تستقبل طلب وترجع صفحة.

### URL

رابط يشير إلى View.

### Template

ملف HTML فيه شكل الصفحة.

### Context

قاموس بيانات يمر من View إلى Template.

مثال:

```python
return render(request, 'cars/index.html', {'cars': cars})
```

في HTML تستطيع استخدام:

```django
{{ cars }}
```

### QuerySet

نتيجة بحث من قاعدة البيانات.

مثال:

```python
CarSpecification.objects.filter(brand_ar='تويوتا')
```

يعني: اجلب سيارات تويوتا.

## 18. جاهزية الإنتاج والتشغيل

قبل نشر الموقع على الدومين الحقيقي يجب تشغيل:

```bash
python manage.py check --deploy --settings=config.settings
```

يوجد فحص مخصص داخل `cars/checks.py` يتحقق من أهم متطلبات الإنتاج:

- وجود دومين عام داخل `ALLOWED_HOSTS`.
- عدم الاعتماد على SQLite في الإنتاج، بل ضبط `DATABASE_URL` لـ PostgreSQL.
- تغيير مسار لوحة الإدارة عبر `ADMIN_URL` وعدم تركه `admin/`.
- ضبط `CSRF_TRUSTED_ORIGINS` للدومينات الحقيقية.
- ضبط النسخ الاحتياطي عبر `BACKUP_GITHUB_REPO` و`GITHUB_BACKUP_TOKEN`.
- ضبط `BACKUP_ENCRYPTION_PASSPHRASE` حتى تكون النسخ المرفوعة مشفرة.

## 19. النسخ الاحتياطي

سكربت النسخ موجود في:

```text
scripts/backup.sh
```

يشمل النسخ:

- الشفرة الأساسية.
- ملف `.env`.
- قاعدة البيانات: PostgreSQL عبر `pg_dump` أو SQLite محلياً إذا لم يوجد `DATABASE_URL`.
- ملفات `media`.

إذا وُجدت `BACKUP_ENCRYPTION_PASSPHRASE` يقوم السكربت بتشفير النسخة قبل رفعها. إذا لم توجد، يرفض الرفع افتراضياً حتى لا تُرفع أسرار `.env` بشكل غير مشفر. يمكن تجاوز ذلك فقط بقيمة صريحة:

```env
BACKUP_ALLOW_UNENCRYPTED=True
```

وهذا غير موصى به.

## 20. إعلانات البطاقات بعد مبدأ الفصل

نظام الإعلانات لم يعد إعلاناً واحداً لكل البطاقات فقط. الحقول الجديدة في `AdBanner`:

- `gateway_card_target`: يحدد بطاقة رئيسية معينة لإعلان `gateway_card`.
- `target_dealer`: يحدد وكيلاً معيناً لإعلان `dealer_card`.

إذا تُرك الاستهداف فارغاً، يستخدم الإعلان كاحتياطي عام:

- إعلان عام لبطاقات الرئيسية التي لا تملك إعلاناً مخصصاً.
- إعلان عام لبطاقات الوكلاء الذين لا يملكون إعلاناً مخصصاً.

هذا يحافظ على السلوك القديم بدون كسر، ويضيف مبدأ الفصل لكل بطاقة.

## 21. حالة الفحص الأمني الأخيرة

- `python manage.py check --deploy`: يمر بلا ملاحظات عند ضبط متغيرات الإنتاج المطلوبة.
- `pip-audit`: لا توجد ثغرات معروفة ضمن قيود `requirements.txt` الحالية.
- `bandit`: لا توجد نتائج أمنية فعلية بعد مراجعة الاستثناء الموثق في فحص `ALLOWED_HOSTS`.
- Pillow مقيد بالإصدار `12.3.0` أو أحدث ضمن السلسلة 12 لإغلاق ثغرات الإصدارات السابقة.
- أكواد الخصم تستخدم `secrets.randbelow` بدلاً من المولد العام `random`.
- مفتاح التطوير مؤقت وعشوائي، والإنتاج يرفض الإقلاع من دون `SECRET_KEY` بيئي.
- الاختبارات الحالية: 36 اختباراً.
