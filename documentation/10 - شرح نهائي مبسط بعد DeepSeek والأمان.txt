شرح نهائي مبسط — الحالة الحالية (2026-09-14)
=============================================

آخر تحديث: حذف "شكد فلوسك" بالكامل، إضافة دليل الوكلاء، إضافة عدادات تراكمية، تحسين لوحة الإدارة، إصلاح Excel، وإصلاح واجهة البحث وتثبيت التطبيق.


=========================================================================
1) القرار الحالي
=========================================================================

تم إلغاء "شكد فلوسك" من الواجهة والكود وقاعدة البيانات.

البديل الرسمي في الواجهة:
- وكلاء الزيوت وقطع الغيار

الرابط الحالي:
- /dealers/

الرابط القديم:
- /budget/ لم يعد مستخدماً وتمت إزالته من المسارات.


=========================================================================
2) التحكم من لوحة الإدارة
=========================================================================

يمكن التحكم بظهور بطاقة الوكلاء من:

لوحة التحكم > إعدادات الموقع > بطاقات الواجهة > إظهار بطاقة وكلاء الزيوت وقطع الغيار

الوضع الافتراضي:
- البطاقة مخفية.
- صفحة /dealers/ تحول المستخدم إلى الصفحة الرئيسية إذا كانت الميزة غير مفعلة.

إذا كان الخيار مفعلاً:
- تظهر البطاقة في الصفحة الرئيسية.
- يمكن فتح صفحة /dealers/.

إذا كان الخيار غير مفعل:
- تختفي البطاقة من الصفحة الرئيسية.
- صفحة الوكلاء لا تظهر للزائر.


=========================================================================
3) إدارة الوكلاء
=========================================================================

يمكن إضافة وتعديل وإخفاء الوكلاء من:

لوحة التحكم > وكلاء الزيوت وقطع الغيار

حقول الوكيل:
- نوع الوكيل: وكلاء الزيوت أو وكلاء قطع الغيار.
- تصنيف قطع الغيار: عام، ياباني، صيني، إيراني، أمريكي، ألماني.
- اسم الوكيل.
- المحافظة.
- العنوان.
- رقم الهاتف.
- رقم واتساب.
- رابط الموقع أو الصفحة.
- الماركات / الاختصاص.
- تفاصيل الوكيل.
- ظاهر في الموقع.
- وكيل مميز.
- الترتيب.


=========================================================================
4) صفحة الوكلاء
=========================================================================

صفحة /dealers/ تعرض عند تفعيل الميزة:
- تبويب وكلاء الزيوت في العراق.
- تبويب وكلاء قطع الغيار.
- فلاتر قطع الغيار: عام، ياباني، صيني، إيراني، أمريكي، ألماني.
- بطاقات وكلاء محسنة بصرياً.
- أزرار اتصال، واتساب، وموقع عند توفرها.

كل البيانات المعروضة تأتي من لوحة التحكم فقط.


=========================================================================
5) العدادات والإحصائيات
=========================================================================

تمت إضافة عدادات تراكمية داخل النظام:
- عداد ضغط زر تثبيت التطبيق.
- عداد التثبيت الفعلي للتطبيق عندما يرسل المتصفح حدث appinstalled.
- عدادات نقرات تواصل الوكلاء: اتصال، واتساب، موقع.

العدادات تراكمية:
- لا تُصفّر يومياً.
- لا توجد آلية تصفير تلقائي.
- لا تحفظ أسماء المستخدمين أو بيانات شخصية.
- يتم تصفيرها يدوياً فقط من لوحة الإدارة.

يمكن من لوحة الإدارة:
- تصفير عداد واحد.
- تصفير عدة عدادات محددة.
- تصفير كل عدادات تثبيت التطبيق.
- تصفير كل عدادات تواصل الوكلاء.

- تصدير Excel.
- استيراد Excel.

حقل الفئة trim موجود أيضاً ويظهر في:
- لوحة الإدارة.
- فلترة البحث.
- بطاقات البحث عند توفر القيمة.
- تصدير Excel باسم Trim.
- استيراد Excel من عمود Trim أو Class.

تم حذف حقول سعر الصرف من إعدادات الموقع:
- exchange_rate_iqd_per_usd
- exchange_rate_source

السبب:
- لم تعد مستخدمة بعد حذف شكد فلوسك ونظام الميزانية.

=========================================================================
9) واجهة البحث وتثبيت التطبيق
=========================================================================

تم إصلاح واجهة البحث:
- ترتيب بطاقات البحث على الكمبيوتر أصبح عمودياً مثل الهاتف لمنع تداخل الأزرار.
- زر البحث وإعادة التعيين أصبحا ضمن صف صحيح ومتجاوب.
- بطاقة البحث تعرض Engine Code و Spark عند توفرهما.

تم إصلاح زر تثبيت التطبيق:
- الزر أصبح ظاهراً دائماً كزر تثبيت/إرشادات.
- إذا كان المتصفح يدعم نافذة التثبيت المباشر تظهر النافذة الأصلية.
- إذا لم يدعمها المتصفح تظهر نافذة تعليمات التثبيت اليدوي.
- زر "حسناً، فهمت" يغلق النافذة بشكل صحيح.

حالة الأوفلاين:
- Service Worker يستخدم Network-first.
- عند انقطاع الإنترنت تظهر آخر نسخة محفوظة من الصفحة إذا زارها المستخدم سابقاً.
- إذا لم تكن الصفحة محفوظة يحاول الرجوع إلى الصفحة الرئيسية المحفوظة.
- لا توجد صفحة أوفلاين مخصصة حالياً.


=========================================================================
10) النسخ الاحتياطي
=========================================================================

يوجد cron يومي على السيرفر:
- 15 3 * * * cd /var/www/sayarti && bash scripts/backup.sh >> /var/log/sayarti_backup.log 2>&1

تم إصلاح scripts/backup.sh:
- كان الرفع إلى GitHub يفشل بسبب وجود تاريخ سابق في مستودع النسخ.
- أصبح السكربت يعمل clone/pull لمستودع النسخ قبل push.
- تم اختبار نسخة يدوية ورفعها بنجاح إلى مستودع sayarti-full-backup.


=========================================================================
11) GitHub والخصوصية
=========================================================================

لجعل مستودعات GitHub مخفية:
- افتح GitHub.
- ادخل إلى المستودع المطلوب.
- اختر Settings.
- انزل إلى Danger Zone.
- اختر Change repository visibility.
- اختر Make private.
- أكد اسم المستودع عند الطلب.

مستودعات مهمة يجب أن تكون Private:
- sayarti إذا كان يحتوي كود الموقع الكامل.
- sayarti-full-backup لأنه يحتوي نسخ قاعدة البيانات والملفات.

تنبيهات مهمة:
- لا ترفع ملف .env أبداً.
- لا ترفع db.sqlite3 أو media إذا كانت تحتوي بيانات حقيقية.
- لا تضع مفاتيح API داخل الكود.
- إذا كان المستودع كان Public سابقاً وفيه أسرار، يجب تدوير الأسرار حتى لو جعلته Private لاحقاً.
- استخدم GitHub Settings > Secrets and variables لأي أسرار خاصة بالـ Actions.


=========================================================================
12) فحص الأمان الحالي
=========================================================================

نقاط جيدة موجودة:
- DEBUG افتراضياً False.
- SECRET_KEY مطلوب من البيئة في الإنتاج.
- ALLOWED_HOSTS لا يسمح بـ wildcard في الإنتاج.
- تفعيل HTTPS hardening في الإنتاج.
- تفعيل HSTS و Secure Cookies و HttpOnly Cookies.
- تفعيل X-Frame-Options DENY و Content-Type nosniff.
- ملف .env وقاعدة SQLite والوسائط داخل .gitignore.

إصلاحات أمان تم تطبيقها:
- منع Service Worker من تخزين صفحات admin و services و verify والتقارير الحساسة.
- احترام Cache-Control: no-store قبل تخزين الردود في الكاش.
- تحويل تصفير عدادات التثبيت والوكلاء في الأدمن من GET إلى POST.
- إضافة CSRF لأزرار تصفير العدادات في لوحة الإدارة.
- حماية تصدير Excel من Formula Injection عبر تعطيل القيم التي تبدأ بـ = أو + أو - أو @.
- جعل DATABASE_URL يطلب SSL/TLS في الإنتاج افتراضياً.

نقاط متبقية تحتاج قرار لاحق:
- مفاتيح AI و Google Analytics Service JSON مخزنة في إعدادات الموقع داخل قاعدة البيانات؛ الأفضل نقلها إلى .env أو تشفيرها.
- Content-Security-Policy يحتوي unsafe-inline بسبب وجود JavaScript و CSS داخل القوالب؛ الأفضل لاحقاً نقلها إلى ملفات static أو استخدام nonce/hash.
- بعض روابط /admin/ مكتوبة يدوياً في القوالب؛ الأفضل لاحقاً استبدالها بروابط Django named URLs إذا تم تغيير ADMIN_URL.
- لا توجد صفحة أوفلاين مخصصة، الموجود حالياً يعرض آخر نسخة محفوظة فقط.

13) الصيانة والأعطال
=========================================================================

تمت إضافة قسم مستقل باسم:
- الصيانة والأعطال

الرابط:
- /maintenance/

التحكم بظهور البطاقة من:
- لوحة التحكم > إعدادات الموقع > بطاقات الواجهة > إظهار بطاقة الصيانة والأعطال

الوضع الافتراضي:
- البطاقة مخفية حتى تكتمل البيانات.
- الصفحة نفسها تعمل ويمكن تجهيز البيانات من لوحة الإدارة.

الأدوات داخل القسم:
- مترجم كودات الأعطال OBD-II.
- مستكشف أعراض الأعطال.
- جدول الصيانة حسب الممشى.

الجداول الجديدة:
- OBDCode: أكواد الأعطال مثل P0300.
- CarSymptom: الأعطال/الأعراض التي يلاحظها السائق.
- SymptomCause: أسباب كل عرض، وتدار داخل صفحة العرض نفسها ولا تظهر كقسم مستقل.
- MaintenanceTask: مهام الصيانة العامة أو حسب الشركة ونوع المحرك.

استيراد Excel متاح من لوحة الإدارة لـ:
- أكواد الأعطال OBD.
- أعراض الأعطال، مع الأسباب داخل نفس الورقة.
- مهام الصيانة.
